# 23.1.3 auth transport recovery — 2026-10-19

## Cause and fix

At 76%, the stock auth coordinator was repeatedly sending BestHTTP requests to
`server-v2.pixelgun3dserver.com/auth_v2/`. UnityWebRequest/WWW hooks do not cover
BestHTTP, so the apparently self-hosted frontend retained an upstream auth
dependency. Previous September success logs also show socket setup without a
local HTTP auth request; they do not establish when the upstream changed.

`backend_redirect_2313.h` now hooks the unambiguous `HTTPRequest.Send/0` entry,
reads System.Uri.AbsoluteUri and applies the existing retired-host routing.
It allocates a managed System.Uri and uses HTTPRequest.set_Uri before the stock
send method queues I/O. Method metadata is resolved once and validated before
installation. No guessed production object offsets, fake HTTP responses,
forced auth states, preference edits or loading-percentage changes are used.
Non-retired requests, including the ordinary internet connectivity probe, keep
the stock path. URL queries/fragments are masked in redirect/socket diagnostics.

The backend must also include the matching binary auth_v2 response fix. A
JSON-only reply cannot be parsed by this build's decoder at RVA 0x3C1554C.
